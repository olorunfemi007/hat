## Findings

1. **Organization member management is blocked.** `/org` displays `Failed to load members: structure of query does not match function result type`. `supabase/migrations/0010_list_org_members.sql:57` returns `u.email` directly, but declares the return column as `text`. Local Supabase's `auth.users.email` is `character varying`. The shim in `supabase/local-test/00b_shim_auth_users.sql:25` uses `text`, masking the incompatibility. Recommended fix: explicitly cast `u.email::text` and make the test shim match Supabase's actual column type; verify against real local Supabase as well.
2. **Sign-in loses the intended destination.** Visiting `/devices/claim` while signed out correctly redirects to `/sign-in?redirect_to=%2Fdevices%2Fclaim`, but signing in lands on `/dashboard`. `src/app/auth/actions.ts:43` hardcodes that destination.
3. **Form accessibility gaps.** Browser inspection found inputs/selects without associated labels: sites 2, claim 2, storage 5, organization 3 in the fresh admin account. Visible adjacent labels are not programmatically connected to these controls.
4. **Claim URLs do not prefill credentials.** Navigating with `serial_number` and `claim_code` query parameters leaves both fields empty. Treat this as a missing capability if QR-driven claiming is required; manual claiming works.
5. **Default Turbopack production build could not complete in this environment.** Both initial and escalated attempts failed with `binding to a port: Operation not permitted`. The Webpack production build succeeded. This is an environment limitation, not evidence of a TypeScript/build-source defect.

6. **Mobile horizontal overflow.** At a 375px viewport, document widths were dashboard 438px, sites 504px, devices 425px, claim 411px, storage 411px, and organization 550px. All six main routes require horizontal scrolling with the audit data. Screenshots are in `/private/tmp/hardhat-audit/mobile-*.png`.

## Completed remediation

- Added `0011_member_email_type.sql`, applied it to the running local Supabase database, and changed the SQL fixture email column to `varchar(255)`. The existing 137 assertions pass with this realistic type. Existing deployed databases need migration 0011; no hosted database was changed.
- Sign-in validates and preserves local destinations with queries. Claim URL parameters prefill both fields after sign-in. External, backslash, control-character, and normalized protocol-relative redirect attempts fall back to the dashboard. Three automated redirect tests pass with `npm test`.
- Associated visible labels with their fields throughout the portal, including authentication, onboarding, claim confirmation, and editing forms. Added accessible names to the organization switcher and member role controls.
- Reworked the shared shell into wrapping navigation and a stacked layout on narrow screens, constrained controls, and allowed long content to wrap. All six main routes have no horizontal overflow and no unnamed form controls at 320px, 375px, and 1280px in the regression run. Site/device edit forms also pass at 320px.
- Fixed stale organization headers by awaiting the switch action and invalidating the shared layout. Confirmed heading and selected organization update together. Renaming also invalidates the shared layout.
- Member role selects now reflect persisted roles, including restoring the correct display when last-admin demotion is rejected. Successful changes to another member were tested, reloaded, and restored.
- The default `npm run build` uses Webpack and now passes compilation, TypeScript, and page generation in this environment. Lint passes.

Browser regression: 25 checks passed, with no browser runtime errors. Results are saved in `2026-09-10-fixes-results.json`; the diagnostic runner is `/private/tmp/hardhat-audit/fixes.cjs`. This remains targeted regression coverage rather than proof of every possible behavior.
